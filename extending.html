Adding your own checks to Odoo Doctor

Any Odoo module can add checks to Odoo Doctor. They are scanned, scored, ignored, switched off and shown with the others, and they get a settings record (severity, limit) like every built-in check.

This page lists what a module may rely on. It is a public interface: these names change only after a deprecation period, and are never removed in a single release. A change is announced in the release notes at least one release before it takes effect, and the old name keeps working until then. Anything not listed here is internal and may change in any release.

odoo_doctor/tests/test_extension.py is the executable version of this page: it adds a check the documented way and fails when something here stops working.

Depend on the module

# __manifest__.py
'depends': ['odoo_doctor'],

Use odoo_doctor_lite instead when you only need the scan engine. The howto and doc_url keys below belong to Odoo Doctor (the paid version); with Lite alone they are ignored.

Add a check

Extend doctor.scan._get_checks(): append your definitions to super() and write the method each one names.

from odoo import _, api, fields, models


class DoctorScan(models.Model):
    _inherit = 'doctor.scan'

    @api.model
    def _get_checks(self):
        return super()._get_checks() + [{
            'code': 'myapp_orphan_orders',
            'name': _('Orders without a customer'),
            'category': 'business',
            'severity': 'medium',
            'method': '_check_orphan_orders',
            'description': _('An order without a customer cannot be invoiced.'),
            'requires': 'myapp.order',
            'threshold': (30, _('Days since the order')),
            'howto': _('Open each order and choose its customer, or cancel it.'),
            'doc_url': 'https://example.com/docs/orphan-orders',
        }]

    def _check_orphan_orders(self):
        days = self._threshold('myapp_orphan_orders')
        since = fields.Datetime.subtract(fields.Datetime.now(), days=days)
        orders = self.env['myapp.order'].search([('partner_id', '=', False), ('create_date', '<', since)])
        if not orders:
            return None
        return self._issue(_('%s orders have no customer.', len(orders)), 'myapp.order', orders.ids)

The check definition

KeyRequiredMeaning
codeyesUnique and stable: settings, ignore reasons and the history are kept under this code. Prefix it with your module.
nameyesShort title shown in the lists.
categoryyesOne of security, system, accounting, data, business.
severityyescritical, high, medium, low or info. info never lowers the score.
methodyesName of the method of doctor.scan that runs the check.
descriptionyesWhy it matters, shown on the issue.
requiresnoA model name. When it is not installed the check is skipped with a clear reason.
thresholdno(default value, label): a limit the user can change in the check settings. Read it with self._threshold(code).
howtonoSteps to fix a finding (Odoo Doctor). Kept as you give it.
doc_urlnoLink to a documentation page, shown with the steps (Odoo Doctor). Kept as you give it.
fixnoName of a _fix_* method that takes the doctor.result record, for a Fix button.
fix_labelnoLabel of that button.

Odoo Doctor fills in howto and doc_url only for its own checks; a check of yours without them still runs.

The check method

  • Return a falsy value (None) when the check passes.
  • Return self._issue(message, res_model=None, ids=None, count=None, severity=None) when it finds something. ids are the affected records of res_model (the user can open them); count replaces len(ids) when you list fewer records than you found; severity overrides the one of the definition for this finding.
  • Return self._skip(reason) when the check cannot say anything here (a setting does not apply, an app is missing).
  • Raise nothing on purpose: an exception stops only your check, which then shows as "The check could not run".
  • It runs with sudo(), in its own savepoint. It sees every record whoever started the scan, exactly as the nightly scan does. It must only read.
  • self._threshold('<code>') returns the limit set by the user, or the default of the definition.

Stable names

  • The definition keys above.
  • The methods _get_checks(), _issue(), _skip() and _threshold() of doctor.scan, with the arguments shown.
  • The category names security, system, accounting, data and business, and the severities critical, high, medium, low and info.
  • The check codes of Odoo Doctor itself: a check moves between Odoo Doctor and Odoo Doctor Lite without changing its code, so settings and history carry over.

Before you publish

Install your module with Odoo Doctor on a copy of your database and run a scan: a check that fails there shows as "The check could not run" with the reason.
